# TASK P1-03 — Database foundation

## OBJECTIVE
The API can talk to PostgreSQL through Drizzle with migrations, conventions and real-database integration tests, so every later module starts from the same base.

## BACKGROUND
Depends on P1-01, P1-02. Decisions: D-011 (Drizzle, forward-only migrations). Standards: `docs/ENGINEERING_STANDARDS.md` (IDs, naming, schema-per-module, money/time).

## SCOPE
- `packages/db/` (`@internationalota/db`): Drizzle client factory (node-postgres `pg` Pool), shared column helpers, migration runner script.
- Helpers: `id()` UUIDv7 primary key (generated in app via `uuidv7` package), `timestamps()` (`created_at`, `updated_at` timestamptz, UTC), `money(name)` → `<name>_minor bigint` + `<name>_currency char(3)`.
- One schema `platform` with table `platform.app_meta` (key text PK, value jsonb, timestamps) — only to prove the toolchain.
- API `DatabaseModule` (global provider of the Drizzle client, closes pool on shutdown) and `GET /health/ready` → 200 when `SELECT 1` succeeds, 503 otherwise.
- Root scripts: `db:generate`, `db:migrate`, `db:studio` (optional).
- Test helper `packages/db/test/test-db.ts`: creates database `ota_test_<random>`, runs migrations, returns client, drops DB after the suite.
- Module-boundary check: `dependency-cruiser` config forbidding imports of `apps/api/src/modules/*/` internals except through each module's `index.ts`; root script `lint:boundaries`, added to CI `verify` job.
- CI: add a PostgreSQL service container (same image as compose) to run integration tests.

## OUT OF SCOPE
Any business table, auth, Redis usage, seed data (P1-05), Money arithmetic library (P1-04 — only the column helper here).

## TECHNICAL INSTRUCTIONS
1. Allowed new dependencies: drizzle-orm, drizzle-kit, pg, @types/pg, uuidv7, dependency-cruiser.
2. Migrations are SQL files generated by drizzle-kit and committed; never edit an applied migration. Migration runner refuses to run if `NODE_ENV=production` unless `ALLOW_PROD_MIGRATE=1` (production migrations are a separate approved operation).
3. `DATABASE_URL` from env; document in `.env.example`.
4. Every query in later tasks must be able to use row locks (`.for('update')`) — show one in the integration test.

## ACCEPTANCE CRITERIA
- On an empty database `pnpm db:migrate` succeeds; running it again is a no-op.
- Integration test (real Postgres): insert + read `app_meta`; a `SELECT ... FOR UPDATE` in one transaction blocks a second transaction until commit (prove with timing/ordering assertion).
- `/health/ready` 200 with DB up, 503 with DB stopped (test or documented manual check).
- `lint:boundaries` fails on a deliberate illegal import (show output), passes after removal.
- CI green including integration tests.
